# Kyro: $0 prelaunch marketing plan

**Created:** 7 November 2026 (NZDT) · **Status:** execution preparation, not a general public-beta approval  
**Scope:** public website, Genesis reference research, Kyro invite-only private-alpha collaboration and honest demonstrations.  
**Budget:** USD 0 new marketing spend; do not enable paid AWS resources, marketing SaaS trials that auto-bill, domains, ads, or paid social tools. Existing AWS costs may continue and are NOT guaranteed to be $0.

## One product narrative

**Kyro — Build together. Grow with knowledge.**  
Kyro is the user-facing research and collaboration interface; Genesis is the model and modular knowledge reference; Aurora is the separately controlled execution engine.

Verified descriptions only:
- GitHub includes open-source Genesis **data-only** examples for Spanish, te reo Māori and physics; local install/search/disable/uninstall in the reference runtime, not cloud self-service.
- Kyro collaboration research includes project files, team discussion and role-scoped private-alpha capabilities, **not** live co-editing.
- The public V3 read-only workspace preview and static public information site can be explored. Restricted login and model quality require further testing.
- Aurora protected production execution, AGI, accredited expertise, hosted module purchases and public onboarding **must not** be advertised as working.

## Six-week editorial cadence (not automated)

Week 1 — Publish accurate public narrative and recruit developer reviewers via GitHub.  
Week 2 — Publish a local Genesis reference-pack walkthrough and its limits.  
Week 3 — Demonstrate Kyro private-alpha permissions with synthetic project data.  
Week 4 — Describe Aurora/Genesis trust boundaries and public contract tests.  
Week 5 — Report acceptance testing, failure rates and fixes, without inventing results.  
Week 6 — Review readiness gates and decide whether any external preview submission qualifies.

Do **not** spam, buy followers, ask for Product Hunt votes, use unapproved screenshots, or mass-register fake interest.

## Funnel and metrics

Proposed goals **not forecasts**: 500 interested visitors, 100 valid early-interest submissions, 20 genuine test users. Track only what can be verified. GitHub issue submissions are **public**, so do not export or maintain an unnecessary personal-data list.

- `exposures`: count documented posts and reach when a platform reports it.
- `visits`: only from privacy-reviewed aggregate site statistics (currently unavailable, mark N/A).
- `interests`: distinct public GitHub issues created with the early-access template; do not interpret stars as signups.
- `active_testers`: only verified distinct testers after approved, invitation-only test runs.
- `retained`: only test runs on multiple days, based on lawful/approved telemetry.
- `feedback`: count actionable issues and whether acknowledged/resolved.

Write weekly aggregate totals into `docs/marketing/METRICS_TEMPLATE.csv`. Never fabricate measurements or include names/emails in CSV.

## Blockers vs improvements

**Blockers:** browser PKCE acceptance; account isolation; public privacy notice and data lifecycle; cost controls/alerts; secure recovery/rollback; model quality; acceptable demo; moderation capacity; legal review before broad signup.  
**Improvements:** screenshots, brand imagery, scheduled posts, product catalogue polish, SEO, video editing.
