# Aurora, Genesis and Kyro — Public Systems Guide

Kyravantra's experimental platform separates execution, cognition and interaction. This document describes design intent, not proof of deployment or release qualification.

| System | Purpose |
| --- | --- |
| **Aurora — Engine** | Execution boundaries, process and resource lifecycle, independent operational authorization |
| **Genesis — Model** | Reasoning, planning, memory and semantic decisions |
| **Kyro — Interface** | Account-aware access to permitted platform services and public information |

**Core boundary:** Genesis interprets requests, while Aurora independently decides whether permitted execution may proceed. Kyro is an interface, not a substitute for either authority.

The public software includes selected Genesis research references, interoperability specifications, examples and Kyro website source. Protected Aurora internals and operational details remain private.

## Maturity

Designs and specifications are not automatically implemented. Implemented reference code is not necessarily deployed. Passing local tests is not the same as independent, production-grade qualification. No claim of AGI, consciousness, unrestricted autonomous execution or production certification is made.

The public information website is separate from the authenticated Kyro research workspace; access is restricted where appropriate.

## Publication boundary

We publish reviewed technical interfaces and reference material so that developers can evaluate interoperability without revealing protected Engine source, security findings, operational infrastructure, or user records. See [publication policy](../../PUBLIC_PRIVATE_BOUNDARY.md) and [project status](../governance/PROJECT_STATUS.md).
