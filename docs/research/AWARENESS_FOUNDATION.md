# Genesis Awareness Foundation — research prototype v0.1

**Scope:** measurable *functional awareness*, not machine consciousness, sentience, or AGI.

## Boundaries

- **Genesis** owns self-description, limited attention, decision monitoring, metacognitive evaluation, and introspectable diagnostics.
- **Aurora** remains authoritative for runtime/sensors, scheduling, interlocks, protected observability, Angels, and execution. The prototype ingests no unverified signals as Engine truth.
- **Kyro** may use `GET /awareness` as a read-only display. No public endpoint for injecting feedback or changing capability levels.
- Guardian, constitutional and capability gates are unchanged. Awareness cannot self-authorize work or update policy.

## First implemented cycle

`input metadata → attention event → existing cognition/authorization → decision trace → failure/uncertainty detection → bounded persistence → read-only introspection`

Each observation deliberately retains *no raw prompt/response*. Operational action success and semantic correctness are distinct: reported confidence does not establish calibration. Only **independently checked** labels entered by a trusted offline evaluator contribute to Brier score and observed accuracy; 30 labels is a minimal **sampling indicator**, not statistical certification.

## Acceptance criteria

1. Self-model reports Genesis' role and capability ceiling without claiming Engine authority or attested sensors.
2. Attention workspace is bounded (1–20), salience-ranked and persisted through SQLite.
3. Failed decisions and low/unknown confidence generate inspectable signals.
4. Calibration stays unavailable before verified correctness feedback, and rejects conflicting/unrecognized labels.
5. No user prompts, model generations, or Engine secrets stored in awareness events.
6. No changes to Guardian, Aurora authorization, or execution paths.

## Next gates

- Establish real feedback datasets: domains, verifier provenance, error correction, confidence calibration curves, selective abstention metrics.
- Implement perception/belief model with evidence, contradiction detection, staleness and open-world unknowns.
- Add Aurora-attested, schema-checked runtime sensor interface **only after** actual Engine verification is available.
- Introduce safe attention goals and task-focused control-policy experiments with independent benchmarks.
- Add user-control for telemetry retention, export and privacy reviews.
